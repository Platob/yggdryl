# Amazon S3

Objects on S3 as three [`IOBase`](../iobase/bytes.md) handles: `Path` a location, `Folder` a prefix or bucket, `File` one object.

## Contract

| | |
| --- | --- |
| Owns | `holder::s3::{Path, Folder, File}`, the `IOPath`, `IOFolder`, `IOFile` roles of [Holder](../index.md) |
| Feature | `s3`, not default: the signed client and its TLS stack are a cost a local consumer never pays |
| Bindings | An `s3:` [`Url`](../../uri/index.md) selects this backend; the knobs stay Rust-only |
| Protocol | The S3 REST API directly - SigV4 over synchronous HTTP/1.1. No SDK, no async runtime, no object-store layer |
| Lazy | Constructing touches nothing; credentials, region, and endpoint resolve on the first request |
| Addressing | Virtual-hosted on AWS, path style elsewhere or when the bucket holds a dot; `with_path_style` overrides |
| Absence | A missing object reads empty and sizes zero; a delete of nothing succeeds; a refusal is `Error::Remote` |
| Credentials | Explicit, then the URL, the environment, `~/.aws`, the container endpoint, IMDSv2, then anonymous |
| Secrets | Keys written into a location sign the request and are stripped from the URL the handle reports |
| Payload | Signed over plain HTTP, `UNSIGNED-PAYLOAD` over HTTPS where TLS already covers it; `with_payload_signing` overrides |
| Pooling | One connection serves many requests; a ranged read drains its body so it stays reusable |
| Encryption | `SSE-S3`, `SSE-KMS` with a named key and a context, and `SSE-C`; a customer key is carried on reads too |
| Identity | The credential chain, or an STS role it is traded for; the session is refreshed before it lapses |
| Configuration | `S3Options::with_properties` reads PyIceberg's `s3.*` names, PyArrow's arguments, and the AWS environment's |

## What each operation costs

This is the contract the backend exists for, so it is stated as a number and
asserted by tests rather than intended. `Folder::stats`, `File::stats`, and
`Path::stats` report what actually went out.

| operation | requests |
| --- | --- |
| building any handle, resolving a child, reading a media type or a partition | none |
| resolving a `lake/` location | none - the slash already said it is a container |
| resolving any other location | one listing of a single key, or two |
| a ranged read | one ranged `GET`, transferring the range |
| a whole read, a full stream drain, or a digest of any size | one `GET` |
| the size of a listed object | none - the listing already stated it |
| `size` on a closed handle | one `HEAD`; none while open |
| a whole write | one `PUT`, or `parts + 2` above the multipart threshold |
| an append | one `GET` and one `PUT`; S3 has no append, and none of the `GET` while open |
| a removal | one `DELETE`, issued without a probe |
| a listing, one level or a whole subtree | one request per 1000 entries |
| emptying or removing a prefix | one listing and one bulk delete per 1000 keys |

Three of those are worth spelling out.

**Resolving a location** is one listing bounded to a single key: a key is the
smallest string starting with itself, so an object there is the first answer,
and a key under it coming back instead says the location is a prefix. The
second listing settles the case neither answer covers - `.` is `0x2E` and `/`
is `0x2F`, so `lake/part.parquet` sorts *between* `lake/part` and the keys
under `lake/part/`, and a sibling spelled that way hides the prefix from the
first answer.

A **recursive listing** is one flat listing, not one request per directory: S3
answers keys in byte order, which already is depth-first pre-order once the
containers a key implies are emitted before it, so a lake of ten thousand parts
across a thousand partitions costs ten requests rather than a thousand. A key
spelled with a trailing slash is a directory marker, and it lists once, as the
container it names.

A **ranged read learns the object's length** from the `Content-Range` it comes
back with, so a scan that reads and then asks the size pays nothing for the
answer.

## Use

Every binding reaches the same handles through an `s3:` URL. Rust and Python
also take the knobs - Python as an `options` mapping on the three role classes,
in whichever vocabulary the caller already has.

=== "Rust"

    ```{ .rust .no_run }
    use yggdryl::IOBase;
    use yggdryl::holder::s3;

    // Credentials, region, and endpoint resolve the way the AWS tools resolve
    // them, and nothing is read until the first request.
    let mut part = s3::file("s3://trades/lake/year=2026/part.parquet")?;

    // A footer read transfers the footer, not the file.
    let footer = part.read_range_bytes(part.size().saturating_sub(8), 8)?;
    assert_eq!(footer.len(), 8);
    ```

=== "Python"

    ```{ .python .ignore }
    from yggdryl import IOBase, S3File

    # The same class, the same methods: the scheme picks the backend.
    part = IOBase("s3://trades/lake/year=2026/part.parquet")
    footer = part.read_range_bytes(part.size - 8, 8)

    # Or the role by name, with the catalog's properties handed over whole.
    part = S3File("trades", "lake/year=2026/part.parquet", options=catalog.properties)
    ```

=== "JavaScript"

    ```{ .javascript .ignore }
    const { IOBase } = require('yggdryl')

    const part = new IOBase('s3://trades/lake/year=2026/part.parquet')
    const footer = part.readRangeBytes(part.size - 8, 8)
    ```

## Naming an object

A location and a name are not the same thing. `s3://trades/a%20b/c.txt` is a
URL; `a b/c.txt` is the key the store uses. `file` and `folder` take the first,
`file_at` and `folder_at` take the second, and encoding belongs to the latter.

```rust
use yggdryl::holder::s3;

let handle = s3::file_at("trades", "lake/a b/part.parquet")?;
assert_eq!(handle.key(), "lake/a b/part.parquet");
assert_eq!(handle.url().to_string(), "s3://trades/lake/a%20b/part.parquet");

// A prefix always ends in the delimiter, whether or not the caller wrote one.
let lake = s3::folder_at("trades", "lake")?;
assert_eq!(lake.prefix(), "lake/");
```

## Reaching a store that is not AWS

MinIO, Ceph, and other S3-compatible gateways are named by their endpoint,
either in the location or through `S3Options`. A port, an IP literal, or
`localhost` in an `s3:` URL names an endpoint rather than a bucket, so a local
store reads the way AWS does.

```rust
use yggdryl::holder::s3::{Credentials, S3Options};

let options = S3Options::default()
    .with_endpoint("http://localhost:9000")
    .with_credentials(Credentials::new("minioadmin", "minioadmin"))
    .with_region("us-east-1");
assert_eq!(options.endpoint(), Some("http://localhost:9000"));

// Options clamp what S3 will not accept rather than refusing it.
assert_eq!(S3Options::default().with_part_size(1).part_size(), 5 * 1024 * 1024);
assert_eq!(S3Options::default().with_list_page_size(50_000).list_page_size(), 1000);
```

Where each unset knob is found:

| knob | URL | environment | `~/.aws/config` | default |
| --- | --- | --- | --- | --- |
| endpoint | hostname, with its port | `AWS_ENDPOINT_URL_S3`, `AWS_ENDPOINT_URL` | `endpoint_url` | `https://s3.{region}.amazonaws.com` |
| region | a recognized AWS hostname | `AWS_REGION`, `AWS_DEFAULT_REGION` | `region` | `us-east-1` |
| credentials | `s3://key:secret@bucket/` | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN` | `~/.aws/credentials` | container endpoint, IMDSv2, then anonymous |
| profile | | `AWS_PROFILE` | | `default` |
| path style | | `AWS_S3_FORCE_PATH_STYLE` | | virtual-hosted on AWS, path style elsewhere |

`with_environment(false)` shuts all of that off, so only explicit values and the
URL decide - which is what a test wants and what a sandboxed process may need.

## Reading somebody else's configuration

A caller rarely starts from this crate's spellings. They start from a PyIceberg
catalog's properties, from the arguments PyArrow's `S3FileSystem` takes, or from
the AWS environment variable names - three vocabularies for one set of knobs.
`with_properties` reads all three, matching names loosely: case, `-`, `_`, and
`.` are the same, and a leading `s3.`, `client.`, or `aws_` is dropped, so
`s3.access-key-id`, `AWS_ACCESS_KEY_ID`, and `access_key` are one knob.

```rust
use yggdryl::holder::s3::S3Options;

// Hand it the catalog's properties whole; what is not about a store is
// ignored, because most of a catalog's properties are not.
let options = S3Options::from_properties([
    ("warehouse", "s3://trades/lake"),
    ("token", "a catalog bearer token, which is not a session token"),
    ("s3.endpoint", "http://localhost:9000"),
    ("s3.access-key-id", "minioadmin"),
    ("s3.secret-access-key", "minioadmin"),
    ("s3.force-virtual-addressing", "false"),
    ("s3.request-timeout", "30"),
])?;
assert_eq!(options.endpoint(), Some("http://localhost:9000"));
assert_eq!(options.path_style(), Some(true));

// A value that will not parse is heard here rather than at the store.
assert!(S3Options::from_properties([("s3.request-timeout", "soon")]).is_err());
// And a knob this client cannot honor is refused rather than dropped, so
// nothing a caller asked for silently does not happen.
assert!(S3Options::from_properties([("s3.signer.uri", "https://signer")]).is_err());
```

| knob | this crate | PyIceberg | PyArrow |
| --- | --- | --- | --- |
| endpoint | `endpoint` | `s3.endpoint` | `endpoint_override`, `scheme` |
| region | `region` | `s3.region` | `region` |
| credentials | `access_key_id`, `secret_access_key`, `session_token` | `s3.access-key-id`, `s3.secret-access-key`, `s3.session-token` | `access_key`, `secret_key`, `session_token` |
| anonymous | `anonymous` | | `anonymous` |
| addressing | `path_style` | `s3.force-virtual-addressing` | `force_virtual_addressing` |
| timeouts | `timeout`, `connect_timeout` | `s3.request-timeout`, `s3.connect-timeout` | `request_timeout`, `connect_timeout` |
| proxy | `proxy` | `s3.proxy-uri` | `proxy_options` |
| role | `role_arn`, `role_session_name`, `external_id` | `s3.role-arn`, `s3.role-session-name` | `role_arn`, `session_name`, `external_id` |
| encryption | `sse_type`, `sse_key`, `sse_md5` | `s3.sse.type`, `s3.sse.key`, `s3.sse.md5` | |
| buckets | `allow_bucket_creation`, `allow_bucket_deletion` | | the same |
| uploads | `part_size`, `multipart_threshold` | `s3.multipart.part-size-bytes` | |
| retries | `max_attempts`, `num_retries` | `s3.retry.num-retries` | |

Sizes may carry the unit a configuration file writes them with - `8MiB`,
`32 MB` - and durations are seconds, whole or fractional.

## Signing as a role

A process that reaches a bucket in another account does not hold keys for it:
it holds keys allowed to *assume a role* that does. One STS request trades the
first for the second, and the session it hands back is what signs the bucket -
refreshed shortly before it lapses rather than asked for per request.

```rust
use std::time::Duration;

use yggdryl::holder::s3::{AssumedRole, S3Options};

let role = AssumedRole::new("arn:aws:iam::123456789012:role/lake-reader")
    .with_session_name("power-desk")
    .with_external_id("desk-42")
    .with_duration(Duration::from_secs(3600));
let options = S3Options::default().with_assumed_role(role);
assert_eq!(
    options.assumed_role().map(AssumedRole::session_name),
    Some("power-desk")
);
```

The credential chain still answers, and what it answers is what signs the
exchange. A session is asked for once and reused until it nears its expiry, so
a thousand reads under a role cost one STS request, not a thousand.

## What a client is not allowed to do

Two lifecycle operations are worth being able to forbid, because a process that
reads a lake has no business creating or destroying a bucket. Both refuse
without a request: it is this client's own rule, and finding out from the store
would be a round trip and an audit-log entry.

```rust
use yggdryl::IOBase;
use yggdryl::holder::s3::S3Options;

let options = S3Options::default()
    .with_bucket_creation(false)
    .with_bucket_deletion(false);
assert!(!options.bucket_creation());

// And every write can carry metadata: a name S3 defines goes over as that
// header, anything else as user metadata, and a name the write sets for
// itself is never displaced.
let options = options.with_default_metadata([("desk", "power"), ("cache-control", "no-store")]);
assert_eq!(
    options.default_metadata()[0],
    ("x-amz-meta-desk".to_owned(), "power".to_owned())
);
```

## Encryption at rest

S3 encrypts three ways, and they differ in *who holds the key* - which is the
same thing as differing in what a request has to say. The choice is a client
knob rather than a per-write argument, because a key the store never keeps has
to be presented again on every read.

| | what a write says | what a read carries |
| --- | --- | --- |
| `Encryption::Default` | nothing; the bucket's own rule applies | nothing |
| `Encryption::Managed` (`SSE-S3`) | `AES256` | nothing |
| `Encryption::Kms` (`SSE-KMS`) | `aws:kms`, and which key | nothing |
| `Encryption::Customer` (`SSE-C`) | the key itself | the key itself |

```rust
use yggdryl::holder::s3::{CustomerKey, Encryption, KmsKey, S3Options};

// The bucket's own default, which is what an unset value means.
assert!(S3Options::default().encryption().is_default());

// A named KMS key, an encryption context KMS records and requires again, and
// an S3 Bucket Key - one KMS call per bucket and window rather than per
// object, which is what makes writing a lake of small parts affordable.
let key = KmsKey::new("arn:aws:kms:eu-west-1:123456789012:key/abcd")
    .with_context(r#"{"desk":"power"}"#)
    .with_bucket_key(true);
let options = S3Options::default().with_encryption(Encryption::Kms(key));
assert_eq!(
    options.encryption().write_headers()[0],
    ("x-amz-server-side-encryption", "aws:kms".to_owned())
);

// A key the caller holds. It is checked here rather than by the store: 32
// bytes, and the MD5 the AWS tools carry beside it has to be the key's.
let held = CustomerKey::from_base64("AwoRGB8mLTQ7QklQV15lbHN6gYiPlp2kq7K5wMfO1dw=")?;
assert_eq!(held.checksum(), "N+iD0sgzzGlyEXJzCNck5w==");
assert_eq!(Encryption::Customer(held).read_headers().len(), 3);

// Nothing renders it.
let key = CustomerKey::new(&[7; 32])?;
assert!(format!("{key:?}").contains("<redacted>"));
```

`PutObject` and `CreateMultipartUpload` say how the object is stored;
`UploadPart`, `GetObject`, and `HeadObject` carry a customer key and nothing
else, because a part inherits how its upload was created and the store
remembers which of its *own* keys it used. `CompleteMultipartUpload` touches no
bytes, so it carries nothing.

## Everything else is inherited

The three roles are the whole backend. Globs, Hive partitions, page caching,
content codings, IPC, Parquet, Avro, and Iceberg tables are not reimplemented
here: they are the [`IOBase`](../iobase/bytes.md) surfaces, and a record reader
over an object is the same reader that runs over a mapped file.

```{ .rust .no_run }
use yggdryl::IOBase;
use yggdryl::holder::buffered::BufferedOptions;
use yggdryl::holder::s3;

let mut part = s3::file("s3://trades/lake/part.parquet")?;
// Opening caches the object's metadata - never its bytes - so the questions a
// reader asks along the way stop being round trips. It is what to do before
// wrapping a remote handle in a page cache.
part.open()?;
let cached = part.buffered(BufferedOptions::default());
let _ = cached.read_range_bytes(0, 16)?;

// One partition of a lake, selected by path alone, with no call per file.
for leaf in s3::folder("s3://trades/lake/")?.children_where(&[("year", "2026")], false)? {
    let _ = leaf?;
}
```

## Failures

Absence and conflict stay the two typed variants every caller already branches
on, so nothing matches on a message. Everything else the store says arrives as
`Error::Remote` with its own code and text intact.

```rust
use yggdryl::Error;

let refused = Error::remote(
    "s3", "GetObject", 403, "AccessDenied", "Access Denied", "s3://trades/lake/part.parquet",
);
assert!(!refused.is_absent());
assert!(!refused.is_conflict());
```

A throttle or a server-side error is retried with backoff; a refusal is not,
because it is the store's verdict rather than a hiccup. A bucket in another
region answers with the region it is in, and the correction is learned once.

## Measured against `object_store`

Both clients run against one in-process store over a real socket, on the same
payloads and keys, so the difference is the two implementations rather than two
networks. Criterion medians on a containerized x86_64 Linux host (Intel Xeon
@ 2.10 GHz, 4 cores, 16 GiB; rustc 1.94.1, thin LTO), `object_store` 0.13.2:

| operation | yggdryl | `object_store` |
| --- | ---: | ---: |
| read 4 MiB whole | 2.16 ms | 2.37 ms |
| read an 8 KiB footer | 62 us | 74 us |
| drain 4 MiB streamed | 1.93 ms | 2.35 ms |
| write 4 MiB, unsigned payload | 9.13 ms | 9.96 ms |
| write 4 MiB, signed payload | 12.31 ms | - |
| first three entries of 2000 | 2.36 ms | 2.80 ms |
| one level of 2000 | 161 us | 180 us |
| whole subtree of 2000 | 7.15 ms | 5.79 ms |

The subtree row is not like for like: this listing yields the container each key
implies as well, which `object_store` does not report at all, so it hands back
half again as many entries for the same pages. The write rows are the same
request under two payload policies, which is why both are given.

A loopback fixture exaggerates fixed cost - a real round trip is 1-20 ms,
against which 60 us is noise - so what these establish is that no per-request
cost is hiding, not that reads are faster in production. The request *count* is
what decides that, and it is held by the accounting tests above.

Regenerate with:

```console
cargo bench --bench holder --features s3 -- s3_ --noplot
```

## Checked against a real store

A hand-written fake store proves the client agrees with itself, and it was
written from the same reading of the API, so the two can agree and both be
wrong. `scripts/check_s3_interop.py` provisions MinIO, has `boto3` write
objects, runs the Rust half against the same store, and then reads back from
the outside every object it wrote - bytes, length, a ranged read, and the
multipart upload, whose assembled content and `-{parts}` ETag are checked by the
reference client rather than by the writer. The exchange keys are the point: a
space, a plus, an equals, a percent, and a non-ASCII name each mean something
different as a URL component, as a signed canonical path, and as a raw key.

```console
python scripts/check_s3_interop.py
```
