The two-value matrix places the `Values` pseudo-field after Product (`colFields x=-2`) and has separate Sales Sum and Units Average grand columns. The nested table emits explicit subtotal row items (`t=default`) for East, West and blank, with 2023/2024 totals 45 and 17 and grand Sales 62. Location offsets differ by layout: `firstDataRow` is 2, 3, 1, 2, 1 for the five cases; the exact offsets and `firstDataCol` are in JSON.

The `source_order_grand` cache preserves source records East 1e16, West 1, East -1e16, West 2. Excel renders East 0, West 3, grand 3 in both COM Value2 and saved sheet XML (`B4:B6` caches `0,3,3`). A naïve left-to-right f64 fold over all source rows would be 2, so that algorithm is contradicted. This observation alone does not identify Excel's internal summation algorithm. Cache definitions differ even for repeated Data sources: some fields use shared indexes, while another cache writes strings directly; consumers must decode each cache's own field metadata.

This fixture does not assert localized captions as English, a Rust implementation, refresh outside this workbook, or any app-wide calculation. The report and generated workbook in `rust/target/excel-desktop/p6-pivot-native` remain the raw evidence.
